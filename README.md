# ZhiGui / 知归

一个由对话唤醒的个人助理系统：把目标、行程、笔记、决策与用户操作保存在同一套关联数据中，让支持 MCP 的 AI 在每次相关对话开始时按需恢复上下文、制定计划并持续跟进。

## 它是什么

知归不是后台自主运行或主动推送消息的机器人。它的可靠边界是：用户在面板或对话中操作后，下一次相关 AI 对话会读取一个紧凑的 Bootstrap 包，理解发生了什么，再读取必要的详情并更新后续计划。

它支持：

- 目标、约束、行程、待安排事项、笔记、决策和后续跟进的显式关联；
- 面板操作与 AI 对话操作写入同一命令层；
- 行程卡片展开关联笔记、目标和决策；
- AI 撰写且按日期冻结的晨间指引；
- 用户完成事项后的活动结算、每日反思与后续关心提醒；
- 标题优先、详情按需读取的分层检索；
- 删除预览、显式确认和关系清理；
- 固定日期事项、时间待定事项、周期事项与可延期工作项的不同处理。

它不会：

- 在用户未打开支持它的 AI 对话时自行说话、发送系统通知或后台执行；
- 因为任务完成自动删除笔记；
- 用单一数字分数替用户决定优先级；
- 把长笔记正文默认塞进每次对话上下文。

## 工作方式

```text
用户面板操作 ─┐
               ├─> 统一 Actions / 关联实体 / 活动日志
用户与 AI 对话 ─┘                 │
                                  v
                    下一次相关对话读取 Bootstrap
                                  │
                  按需读取目标、笔记、日期或决策详情
                                  │
                 形成建议 / 更新状态 / 创建后续跟进
```

面板负责让用户直接查看和操作；MCP 负责让 AI 读取、推理和写入。两者不是彼此的替代品。

## 重要使用约定

1. 完成事项后，如其结果会影响目标、笔记或后续安排，请在下一次对话告诉 AI 结果；AI 才能解释这个事实并更新长期计划。
2. 对话中的“完成了”与面板点击完成都支持同一类影响更新：目标状态、笔记事实、决策和后续跟进应一起写入。
3. 没有明确时间的事项不要伪造时间；有确定日期但没有时间的事项应出现在那一天。
4. 笔记只在确有执行价值时关联到行程；如“取快递”这类自包含事项不需要强行挂笔记。
5. 删除始终先预览影响，再等待用户确认。

详细的 AI 行为规范见 [skill/SKILL.md](skill/SKILL.md)。

## 删除与生命周期

删除是不可逆的：面板与 AI 都会先展示关联影响，再等待确认，并由统一命令层清理失效关系。实体（笔记、目标、决策）有自动生命周期状态：活跃 → 停滞（30 天未引用）→ 归档候选（长期不活跃）。反思引擎只标记候选，不自动删除；清理需用户显式确认。
